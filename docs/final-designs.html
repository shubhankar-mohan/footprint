Claude Control Bar

Final Designs

Every scenario, rendered in both light and dark macOS themes. Palette, spacing and the restrained Marauder's-Map flavor follow the consulting UX designer's brief — footprints are the single motif, texture is felt-not-seen, and Harry-Potter flavor appears only where it's earned.

Companion file: claude-control-bar-design-brief.md (the full UX rationale)
It's a control panel — not a terminal replacement. You still live in the terminal to read the full conversation, Claude's summaries and outputs, and to write detailed prompts. The bar's job is narrow and calm: show every session's state at a glance, let you approve/deny and auto-resume, jump you straight to the right terminal in one click, and start new sessions. It never tries to cram the transcript into a popover — only a one-line glance, then "Open terminal."

The footprint has exactly one job: session state. Usage gets its own glyph — a little hourglass whose sand drains as your budget burns down. 05

Attached session — monitor + reveal

A session you started yourself, seen through global hooks. You can watch and (via hooks) approve/deny. Reveal terminal brings its terminal forward — reliably to the exact tab only for iTerm (via tty match); for Warp/Terminal it activates the app, which is stated plainly. No quick-nudge here: there's no owned input channel.

06

Usage-limit paused — auto-resume

When a session pauses on the usage limit, the footprint freezes. Toggle auto-resume and, the moment the limit resets, the app injects continue into the owned session so it walks on. No countdown pressure — you're in control.

08

Start a session — opens in your terminal

Pick a directory and a terminal — Warp, Terminal, or iTerm. On start, the terminal opens and comes to the foreground so you can type your first detailed prompt right there. Choose a permission mode up front, including --dangerously-skip-permissions for trusted repos. The Managed switch wraps it in tmux so the panel keeps a control channel for approvals, quick nudges & auto-resume. A live command preview shows exactly what will run — nothing hidden.

Why the tmux wrap matters (verified with Claude Code docs). Warp's URI scheme opens a window in a folder but can't run a command, and a raw terminal tab is fire-and-forget — the app can watch via global hooks but can't type into it. Wrapping the launch in tmux (then attaching Warp/Terminal/iTerm to it) is the one clean way to give you a real foreground terminal AND keep a control channel for quick nudges and the continue auto-resume. That's exactly the Owned vs Attached tier split above.

On "click to open the terminal." For managed (tmux) sessions this always works — attach in a fresh foreground window. For revealing a session's existing window, only iTerm is reliable (match the process's tty via AppleScript); Warp and Terminal.app can only be brought to the foreground, not focused to the exact tab. And the correct bypass flag is --dangerously-skip-permissions (= --permission-mode bypassPermissions) — not "allow-permission".
